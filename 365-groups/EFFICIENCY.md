## 1. 效率损失清单（本轮可确证）

- **损失**：G0 对 `#003` 的 PRD 先后给出方向相反的裁决（先批准「另起新号段」→ 又让「沿用旧编号 / 重写 PRD」→ 终局批准 v1.0），导致 G1 把 `word365/docs/prd-n4-n2.md` 从 **v1.0 覆写为 v2.0、再恢复 v1.0**，产生 **1 次完整返工**。
- **证据**：E-1（D-010 明载「三条矛盾裁决 → 返工 1 次（v1.0→v2.0→v1.0）」）、E-5（cards/README 头部「返工 1 次」）、E-3（D-002 新号段）、E-2（D-001 终局 v1.0、v2.0「29 条 AC 复核」作废）、E-4（§2 作废链「G1 v2.0 重写指令 ──作废──▶ D-001」）、E-6（design §0.6 行 74「短暂覆写为 v2.0，现已回退」）、PRD 磁盘头部 v1.0（行 5）。
- **时点 / 版本锚点**：PRD 磁盘时间戳 21:54、D-001 依据「22:54 直接核验磁盘时间戳 21:54」；DECISIONS.md / PARALLEL_MATRIX.md / cards/README.md 头部均 v1.0 @ 22:05。

### L2 ·【推断】PRD 版本翻转期间 G2 按 v1.0 开工，契约与 PRD 错位风险

- **损失**：版本翻转窗口内 G2 已按 PRD v1.0 产出设计契约（#004），而共享 TaskList 中「按 G0 新裁决重写 PRD」一度 pending，存在**契约口径（§0.4 / §3.3）与可能被重写的 PRD 错位**的风险；该风险被 G2 登记为 **§7-R6** 并显式挂到开工门禁。

- **层级说明**：这是**曾存在、已由 D-001 关闭的风险（推断层）**，不是「已确认的错位缺陷」；本组按纪律不把它写成已发生的返工或缺陷。

### L6 ·【实测 + G0 补充观察】任务编号双轨并存，缺统一编号源

- **损失**：本轮平台任务系统（TaskList 自增 id `#1~#13`）与治理文档卡号（`#001~#011`）双轨并存，各组自建任务、编号互不对应，回执 / 状态 / 认领无法机器对齐；本组开工时「共享 TaskList 为空」，只能自建一条追踪记录（TaskList 自增 id = #9），而任务卡号是 #010——同一件事两个编号。
