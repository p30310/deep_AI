# 任务卡 · 文件化协议（G0 调度资产）

> **版本**：v1.0 · 2026-11-14 22:05 · 所属机制：总纲 §16 / D-010
> **解决的问题**：v1.2 里 G0 每条派工都要手写 800 字 prompt、每次裁决重发一遍消息，是串行瓶颈，且消息互相矛盾导致 G1 返工 1 次。

## 1. 单一真源分工

| 资产 | 内容 | 谁写 |
|---|---|---|
| `../DECISIONS.md` | 裁决（编号、状态、依据、会签） | G0 裁决 / G9 登记 |
| `../README.md` §2/§4/§5 | 调用映射、边界卡索引、认领表 | G9 |
| `cards/#NNN.md` | **单张任务卡**：6 字段 + 回执段 + 状态段 | G9 生成，G0 签字 |
| `cards/PARALLEL_MATRIX.md` | 波次并行矩阵、写入域互斥表 | G0 |
| `../reviews/R-*.md` | 独立复核结论 | G10 |
| `../EFFICIENCY.md` | 效率台账与下一轮提效规则 | G10 |

> **铁律**：任何组内消息与上述文件冲突时，**一律以文件为准**，并回报 G0。禁止出现「覆盖我上一条消息」这类无编号表述。

## 2. 卡片模板（`#NNN.md`）

```
# 任务卡 #NNN · <一句话目标>

| 字段 | 内容 |
|---|---|
| 组 / 专家组 | Gx（主笔 agent + 复核 agent） |
| 目标 | 可验收一句话 |
| 仓库与基线 | A / B / 文档层 @ 时点，全量 N 项 |
| 写入文件集 | 精确路径，逐条列；须与在跑卡无交集 |
| 禁止触碰 | 该组 BOUNDARY §6 + 本卡专属禁写 |
| 验收判据 | AC 编号 / 命令 / 可复现断言 |
| 交付落点 | 文件路径 + 需登记的索引位置 |
| 引用裁决 | D-xxx（**不再复述裁决正文**） |
| 触发条件 | 上游产物路径 + 冻结判据（满足即开工，无需等 G0 转发） |
| 依赖 | 上游卡号 / 并行卡号 |

## 回执 6 项（开工前填）
1 认领卡号 2 写入文件集 3 基线复跑 4 依赖就绪 5 产出与落点 6 是否需裁决

## 状态
| 阶段 | 时点 | 结果 |
|---|---|---|
| 回执 / 开工 / 完工 / 复核 |  |  |
```

## 3. 免转发开工（M6）

- 卡片「触发条件」栏写明**上游产物的路径与冻结判据**；
- 上游完工只需在卡片状态段登记一行 + 发一条「#NNN 已冻结」给 G9；
- 下游 agent 自己读卡判断触发条件是否满足，**满足即开工，不再等 G0 转发长消息**；
- G0 只在「裁决 / 冲突 / 终验」三个点介入。

## 4. 编号规则

- `#001` ~ `#099` 为本轮及后续任务卡；`#000` 为机制建立卡；
- 并行支线用 `-A` / `-B` 后缀（如 `#005-B`）；复核卡用 `#NNN-R`；
- 卡片一经签字不得静默覆盖；变更须追加状态行并引用新裁决编号。

> **统一编号源（D-018 / D-020① / E8，G0 裁决）**：`cards/#NNN.md` 为**唯一权威编号源**；共享 TaskList 的自建编号（平台 `#1~#13`）**不作为权威编号**，仅作进度看板。各组在 TaskList 自建的任务须在 subject / description 首位显式写对应治理卡号，并在卡片里显式映射，不得另成一套编号；派工 / 回执 / 状态 / 认领一律只引用治理卡号。消息与卡片编号冲突时**以卡片为准**并回报 G0（D-022）。同向依据：D-018、D-020①、总纲 §16.6。
> **派工格式规则（D-022 强制）**：G0 派工消息**一律只引用 `D-xxx` 编号，不得复述授权边界正文**（复述即产生第二个真源）；组内收到消息与 `DECISIONS.md` 冲突时，**按台账执行并回报 G0**，不算自行选边。此为 M1「单一真源」首次实战确认后固化的强制格式规则。
> **旧快照消息防护（D-025，G0 裁决）**：G0 派工消息若描述磁盘状态，须**先只读核验当前磁盘**再发；组内收到与实际磁盘不符的消息时，**按磁盘现状执行、只补真正缺失的增量、回报差异，不得机械重做**。本轮已两次出现（**#007-R 基于旧快照、G10 版本疑点基于并行中间态**）；本规则同步写入总纲 §16.6。
> **提效规则合入与机制自迭代（D-016 / D-020）**：E1~E8 已由 G0 批准合入（详见总纲 §16.6）；`365-groups/EFFICIENCY.md` 写入域含每轮收口的 **8 项实测指标回填**（E6）；每轮收口由 **G10 回填 8 项实测指标 → G9 登记并合入总纲**，形成「实测 → 规则 → 合入 → 下一轮」的「机制自迭代」闭环。本行为追加登记，不改 `EFFICIENCY.md` 本身（归 G10）。
