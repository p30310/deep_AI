## 完工附件

### A. 语义矩阵（实测四种状态）
| 场景 | `strengthMode` | `strengthFrom` | `rec.last` | 到期取自 | 实测（`todayPlan().reviews.length`） |
|---|---|---|---|---|---|
| 默认 | off | — | — | `r.due`（短路） | 0（该词 40 天后到期） |
| 旧备份/历史 | on | 0 | 任意 | `strengthDue`（全部接管） | 1 |
| 刚开启 | on | now | now−10 天 | `r.due`（未接管） | **0**（不再涌入） |
| 开启后复习过 | on | now−10 天 | now−2 天 | `strengthDue` | 1 |

### B. 关键代码（`js/core.js` · `dueOf`）
```js
function dueOf(r) {
  if (!s || s.strengthMode !== 'on') { return r.due; }
  var from = (typeof s.strengthFrom === 'number' && isFinite(s.strengthFrom)) ? s.strengthFrom : 0;
  if (from > 0) {
    var last = (r && typeof r.last === 'number' && isFinite(r.last)) ? r.last : 0;
    if (last < from) { return r.due; }        // 未复习过 → 保持固定阶梯写入的到期
  }
  return strengthDue(r, Array.isArray(r.evts) ? r.evts : [], null);
}
```

### C. 为什么 `from = 0` 保留「全部接管」
- 兼容 #015/#019 已有的 `strengthMode='on'` 备份（`importJSON` 场景），不改变其行为；
- 使 `core.test.strength.mjs` 的 STR-AC05 断言（on → strengthDue）继续有效，避免"为通过而改测试"；
- UI 永远写真实时刻，用户**无法**再进入「全量重算」状态；该状态只剩理论兼容意义。

### D. 未闭合
- 仍未提供「立即重算全部历史到期」的显式入口——按 Anki 建议（不推荐首次切换时使用）**刻意不做**，避免制造不可逆的复习量冲击。
- 真实老库（数百词）开启后逐词过渡的体验未真机量化；但结构性风险（一次性涌入）已被本卡消除。
