## 完工附件（G0 实现）

### A. 关键实现决策（为什么这么做）
1. **挑战池走 `dueOfWord`**：把 `todayPlan` 内的 `dueOf` 等价提取为模块级函数（10 行、行为逐字段不变），挑战池用它判到期——否则要么复制一份强度接管逻辑（日后必漂移），要么绕开强度层（开启强度后池与今日任务不一致）。提取后既有 40 项相关测试**零改动**通过。
2. **`mode` 只由 `challengeState` 给**：UI 不拼 `if`，避免 CH-AC11（完成态不可重开）与 CH-AC15（空态不可点）互斥失败。
3. **确定性靠 seed 不靠落盘**：`challengePool` 用 `dateKey` 洗完再取前 N（避免每天固定同一批），`challengeQuestion` 用 `dateKey+key` 造题与洗选项，全程无 `Math.random`。
4. **`challengeGrade` 签名不含 `db`**：从类型上杜绝误写 SRS。
5. **点阵只在覆层**：卡面只留文字（G1 否决）；覆层点阵带 `is-current`。
6. **不用原生 `disabled`**：`not-enough` 走 `aria-disabled` + 无 `data-act`，原因不会被 Tab 序列摘掉（G5 v4）。

### B. 五态（与 G5 v4 一致）
| mode | 卡面 | 可点 |
|---|---|---|
| ready（池≥5） | 标题 + `5 个词，约 2 分钟。不改动学习进度。` + 「开始挑战」 | 是 |
| ready（池 1–4） | 标题 + `今天只有 N 个词可挑战` + 「开始挑战」 | 是 |
| not-enough | 标题 + `词库可用词不足 2 个` + 置灰 CTA | 否（`aria-disabled`） |
| empty | 标题 + `今天没有到期的词，也没有错词` + `明天再来看看` | 否（`div`） |
| done | 标题 + `今天已完成 · N 个词` | 否（`div`） |

### C. 未闭合
- 真实浏览器视觉（虚线卡与首页三张实心卡并置的层级效果）、键鼠 Tab 顺序、读屏播报未由 agent 目视。
- 挑战不计入 `days.total`（刻意），因此「只玩挑战的一天」不会增加连续天数——这是 G1 的产品判断，若用户期待计入需另立卡。
