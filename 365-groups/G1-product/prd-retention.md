## 1. 背景 / 目标 / Non-goals

**背景**：统计页四卡 + 热力图 + 柱图全是**过程量**；仪表盘的「保持率」是 `strengthOf.score/6` 的**瞬时估计**，不是「实际是否还记得」。D-054① 要的正是这层缺失的**结果指标**。

**目标（可验收）**
- O1 统计页出现一块**只读**观测卡：给出「间隔 ≥30 天后仍答对的词占比」+ 样本量 + **未到观察期词数**三项事实；不给建议、不给目标线。

**产品叙事（一句可执行）**：*「记下这一项，隔一段（跨越一次 ≥30 天的排程周期）回来再看同一项：同一间隔口径下答对的比例，告诉你复习间隔调过之后，记忆是更稳了还是更松了——这是实测结果，不是曲线估计。」*（慢变量，单点不可解读，须按同口径多次读数看趋势。）

## 2. 指标定义（口径 C，四点写死）

### 2.1 四条口径（G0 裁决方向 + 探针复算）

**① 观察单位 = 词（词级去重，一词一票）。** 对每个词 `w`，取其 `rec.evts` 按 `t` 升序的**相邻事件对** (e_i, e_{i+1})；当且仅当
- `e_i.rating === 'know'`（**起点必须是「认识」**，fuzzy/unknown 不作起点），且
- `gap = e_{i+1}.t - e_i.t >= 30 天`（**下界**，非区间；按毫秒差算，**不做日历天对齐**，跨天自然计入）

则该对是 `w` 的一次**已到期观察**，结果 = `e_{i+1}.rating === 'know' ? 保留 : 未保留`（**fuzzy 与 unknown 同记「未保留」**，与 `app.js:64` 词表、`core.js:230` correct 只在 know 累加同口径）。

**② 窗口内规则（gap < 30 天 → 本次机会作废，锚点让位）。** 起点 know 之后的紧邻事件若落在 30 天内（**窗口内再答**），**既不能判保留也不能判未保留**：该次机会作废，锚点推进到该词的**下一个 know 事件**继续试；若该词再无下一个 know 事件（或 know 之后根本没有后续事件）→ 该词整体记 **pending（未到观察期）**＝契约字段 `pending`（下同）。

**③ 分母 = 保留 + 未保留（= 已到期观察的词数，去重后）；分子 = 保留。** `rate = 保留 / (保留 + 未保留)`；**分母 = 0 时 `rate` 必须是 `null`（不是 0、不是 NaN）**，UI 走空态，**绝不显示「0%」**（0% 会被读成「全忘」）。

**④ pending 必须显示。** pending = 有 know 事件、但至今没有产生任何已到期观察的**词数**（pending 词**不入分母**）。它必须与比率、样本量同屏出现——否则用户会把 1/3 当成「全部词里只有 1/3」，而实际分母只覆盖了 5 词中的 3 词。

**观察总体**：至少含一个 `know` 事件的词（从没「认识」过的词不属本指标，不进分母也不计 pending）。

**为什么用 ≥30 天下界、为什么只取相邻对**：SRS 阶梯 `LADDER_DAYS=[1,2,4,7,15,30,60]`，连续答对的复习间隔依次是 **2/4/7/15/30/60 天**（探针复算）。① 「≥30 天」同时覆盖阶梯仅有的两档长间隔（30、60），而 60 天窗口只剩阶梯顶一档、样本近乎恒 0；若放宽成任意间隔，多数 know 起点 2/4/7 天内就被复习掉 → 指标退化成「复习正确率」，与既有「总正确率」零增量。② 相邻对的间隔 ≈ 系统排定的间隔（含用户迟到），故「间隔 ≥30 天」等价于「**系统确实把这次复习排到了 30 天以外**」= 真实的长期记忆测试点；跨事件累加间隔会把「中间失败过、已回落短间隔」的词误算进来。

### 2.2 每词取**最近一次**已到期观察（G0 终裁）

一个词可能产生多次已到期观察（探针：连续全对的健康词在真实阶梯上可产生 **4 次**，间隔 60/60/60 天）。**只取该词最近一次已到期观察的结果**，此后不再改票。
理由：① **指标要能反映「最近一次长间隔后还记得吗」**——用户读这张卡问的是当下的记忆状态，不是这个词历史上的首次考验；取最近一次 = 词被复习到长间隔档后每次都会刷新结论，与「慢变量、按同口径多次读数看趋势」的产品叙事一致；② 防止同一词在 kept/lost 间反复翻转导致比率抖动；③ 与 G0 终裁措辞一致（PRD 是口径真源）。
代价（登记为偏差）：该词结论会随时间更新 → **两个时点的比率不可直接相减**（必须同时看样本量 M 与 pending C）；且比率随样本轮换而漂移。

**探针数字（首/末口径差异边界，%TEMP% 脚本不入仓）**：连续全对词在真实阶梯上产生 4 次合格观察（间隔 60/60/60）且全部 kept、失守重爬词合格观察数少（重爬回 30 天档需 58 天）→ 两口径**均一致**；仅「先长期答对、后又在 ≥30 天档失守」会分歧（需跨度 ≥88 天，长尾）。故两口径近乎等价，取**最近一次**（G0 终裁），G2 无需为「首个」留分支。

### 2.3 边界与已知偏差（写进实现注释；不得被文案暗示掉）

- 观察总体偏向「已学会（有过 know）」的词；从未 know 过的词完全不参与。pending 会随时间下降（词陆续被排到 30 天以外再考）→ 分母是滚动的。
- 每词只取最近一次观察 → 词的结论会随长间隔复现刷新（这是 G0 终裁要的效果），比率因而随时间漂移；**两个时点的比率不可直接相减**（须同时看 M 与 C）。
- **样本 ≠ 用户整体记忆水平**：分母只是「恰好被排到长间隔、且又被考回来的那一批词」，绝大多数没被长期考过的词完全不在其中；**文案不得出现「你的记忆力」「记得牢不牢」「你能记住多少」这类把样本外推到用户整体的表述**（§3 红线已列，AC13 断言）。
- evts 自 #015（**2026-11-16**）才引入采集 → **任何用户都还没有 30 天 evts 历史**，历史间隔不可回溯；**首批合格观察最早出现在 2026-12-16 前后** → 上线初期的空态是**必然**，不是异常（§5）。
- `evts.interval` 是「距下次**排定**的间隔」，**不是**「距上次作答的间隔」→ 判定间隔必须由相邻两事件的 `t` 相减，**不得使用 `evts.interval`**。
- 纯读与确定性：函数不得修改入参、不得写 `db`、不得调 `saveDB`、不得调 `rateWord`、**不得读 `now()`**；**无 `at` 入参**——判定全是事件间相对间隔、时间基准不进入计算 → 同 db 两次调用必深度相等。撤销天然一致：`core.js:192` 的 `snap.rec` 克隆早于 `:239` push，`undoRate` 回滚会一并回滚该次事件 → 被撤销的作答不残留为观察样本，无需额外设计。
- **出入参（字段名已由 G2 契约定稿，PRD 与契约逐字对齐）**：入参 `db`（只读）、`opts.days`（默认 30）；出参**恰 8 键** —— `window`（生效窗口天数）、`samples`（已到期词数＝分母）、`retained`（保留词数）、`lost`（未答对词数）、`pending`（未到观察期词数＝本 PRD 的 pending）、`rate`（**未取整**原始值，`samples=0` 时 `null`）、`ratePct`（整数百分比，仅供直显）、`state`（`'empty'`／`'insufficient'`／`'ok'`，门槛 10）。不变式：`samples === retained + lost`；`rate === retained / samples`（`samples=0` 时 `null`）；`pending` 不入分母；四个计数**一律＝词**。**`ratePct` 陷阱（AC09 断言）**：`rate=0.004` 时 `ratePct` 同为 0，**不得单独用 `ratePct` 判定** —— `<1%` 与 `0%` 的区分必须读未取整的 `rate`。

## 3. 文案键表（`PHRASES.RETENTION`，逐字，8 键）

| 键 | 逐字文案 | 出现位置 |
|---|---|---|
| `RETENTION.title` | 长期答对情况 | 卡片标题（h3） |
| `RETENTION.lead(M, P)` | 已观察到的 {M} 个词里，有 {P} 在观察窗口过去后仍然答对。 | 主句（15px；**比例只在此句出现一次且内联**，与样本量同句相邻） |
| `RETENTION.leadInsufficient(M, min)` | 样本 {M} 个词，满 {min} 个才显示比例。 | **样本不足态**（1≤M<min）：`lead` 内比例片段整体不渲染，只留纯文字 |
| `RETENTION.leadEmpty(N)` | 还没有可观察的复习：某个词隔 {N} 天以上再考一次、并且那一次也记下来，这里才会有数据。 | **零样本态**（M=0）：`lead` 内比例片段整体不渲染，只留纯文字 |
| `RETENTION.subWindow(N)` | 窗口 {N} 天 | 副标段①（**始终**显示） |
| `RETENTION.subSample(M)` | 样本 {M} 个词 | 副标段②（**仅 M>0**；M=0 时不渲染——0 是「没数据」不是「表现差」） |
| `RETENTION.subPending(C)` | 另有 {C} 个词尚未到观察期，未计入分母 | 副标段③（**仅 C>0**） |
| `RETENTION.note` | 只读统计，不改变复习安排；「模糊」和「不认识」都算未答对。 | 卡片末行（.muted） |

> **副标为条件拼接（D-055②）**：副标＝`subWindow(N)` **恒在** ＋ `subSample(M)`（M>0 时）＋ `subPending(C)`（C>0 时），段间以「 · 」分隔。**不得合成一串**——否则 M=0 会渲染出「样本 0 个词」，与「零样本不显示 0」冲突（D-055 拆三键的原因即此）。
> **两态的区分（G0 第 3 点要求确认）**：`leadEmpty` 与 `leadInsufficient` 视觉上都是「比例片段消失」，但**事实含义不同**，两句逐字已把差异写进文案本身，不靠版式区分：
> - `leadEmpty`（M=0）＝**一个合格观察都还没发生过**：句子说明**需要什么样的记录才会出现**（某词隔 N 天以上再考一次、**且那一次也被记录下来**）——因为 evts 自 2026-11-16 才采集，首批合格观察最早 2026-12-16 前后，**零样本是上线初期的必然状态**，不是用户做错了什么。**零催促、零「再坚持 X 天」式话术、不给预计日期。**
> - `leadInsufficient`（1≤M<min）＝**已经有合格观察、只是数量还不够**：句子说明当前样本量与显示门槛，不解释成因、不提时间。
> - 差异的可判定性：`M=0` 只可能出 `leadEmpty`；`1≤M<min` 只可能出 `leadInsufficient`；两者互斥且必有其一（AC08/AC10 分别断言）。

> 单位取**「个词」**（G0 口径 C：观察单位＝词、词级去重），非 G5 模板里的「次」；契约字段 `samples`/`retained`/`lost`/`pending` **一律＝词数**（**本 PRD 自 v1.4 起统一用契约名 `pending`**，不再用 `pending`）。
> `lead` 的 {P} 为已格式化百分比串（`83%` / `<1%` / `0%`），由 UI 传入，键内不做四舍五入；**判定读未取整 `rate`**（`ratePct` 在 `rate=0.004` 时同为 0，不得单独用它区分 `<1%` 与 `0%`）。
> **跨组硬约束（G5 规格 §2）**：**样本量与比例必须同句相邻**（比例悬空＝无意义小数）→ **比例只允许出现在 `lead` 内且只出现一次**（D-055②：无独立比例位，故无 `ratioLabel` 键），**不得单独成块**；三态的「比例位消失」＝ `lead` 内比例片段整体不渲染，`leadInsufficient`/`leadEmpty` 两句**不含任何百分比**。

**标题硬约束（G5 写死，PRD 遵守）**：标题 = **观察对象的名词短语**，**不得以时段起头**（「N 天…」「最近…」「近 N 周…」一律不可——既有三张图表卡标题全是时段名，时段起头会被读成第四张图表卡）；**窗口天数 N 不进标题**，进副标与主句。
**禁词表（G5，全文与代码零命中）**：保持率 / 留存率 / 记忆率 / 正确率（与统计页「总正确率」撞词）/ 估计 / 预测 / 预估（本块是实测）/ 问号（= 可点暗示，违零交互）/「保持」二字（与仪表盘撞名）。
**文案红线**：零评价、零鼓励、零排名、零达标线、零催促（**禁「再坚持 X 天」「快去复习」「预计 X 月可见」**——空态只说明**需要什么样的记录才会出现**，不给倒计时、不给预计日期）；缺口句必须写「尚未到观察期 / 未计入分母」，**禁**「未答对 / 忘了 / 失败」（pending 是未知，不是错误）；**禁把样本外推到用户整体**（**禁「你的记忆力」「记得牢不牢」「你能记住多少」「说明你记得不错」**——分母只是恰好被排到长间隔又考回来的那一批词，不代表用户整体水平）；所有词取应用既有词表（认识 / 模糊 / 不认识）。

## 5. 冷启动与样本不足

- **样本门限 min = 10**：沿用 `core.js:1289` 抽测池下限 `minPool=10` 的量级直觉，不另造阈值；门限值由契约给出，**UI 不得硬编码第二份**。
- 三态互斥（`M`＝已到期词数＝`samples`）：`M = 0` → `leadEmpty`（`lead` 内比例片段不渲染）；`1 ≤ M < 10` → `leadInsufficient`（同上，且不显示 0%/100%/—/0）；`M ≥ 10` → `lead`（含比例）+ 副标 + `note`。**两态虽同为「比例片段消失」，事实含义不同（零观察 vs 有观察但太少），由文案逐字承担区分**（§3 表下说明、AC08/AC10 断言互斥）。**副标三段条件拼接**：`subWindow` 恒在、`subSample` 仅 M>0、`subPending` 仅 C>0（§3 说明、AC08/AC10 断言）。
- **冷启动是常态不是异常**：`evts` 自 #015（**2026-11-16**）才引入采集 → 任何用户都还没有 30 天 evts 历史，**首批合格观察最早出现在 2026-12-16 前后**；且真实 SRS 阶梯下，**一个词要先连续答对 5 次（间隔 2/4/7/15/30 天）才可能产生第一个 ≥30 天的间隔**（探针复算：首个 ≥30 天间隔出现在第 5 次复习 know@d28→d58）→ 从零到第一个样本以「月」计。**零样本是上线初期的必然状态**，不是用户做错了什么；文案只陈述**需要什么样的记录才会出现**（`leadEmpty`：某词隔 N 天以上再考一次、且那一次也被记录下来），**零催促、零倒计时、零预计日期**（红线见 §3，AC10 断言）。
- **pending 是本卡的主要信息量**：它告诉用户「有 C 个词已经认识、但还没被排到 30 天以外再考一次」——这是排程是否真的走到长间隔的客观痕迹，也是防止把 1/3 误读成「全部」的关键（§2.1④）。

## 6. 与既有统计 / 仪表盘的关系 · 展示位

- **与「总正确率」**：后者 = `core.js:688` 全量作答 correct/total（按**次**，含当天新学）；本卡 = 间隔 ≥30 天的相邻复习对中答对的**词**占比（按**词**、每词一票）。两者分母不同、样本不同，**不可互相替代、不可相减**；既有四卡与文案**零改动**。
- **与仪表盘「保持率估计」**：仪表盘是 `strengthOf.score/6` 的**模型启发式瞬时估计**（每词一点，横轴距上次复习天数，仪表盘 `:324/540/567`）；本卡是**实测结果**（真实发生过的 ≥30 天间隔复习的对错）。D-054④ 点名的混淆风险正来自「同名/同页同读」→ 本卡标题与文案零「保持」字样，且两个数字**不并列进同一张卡**、不做互指文案。
- **与抽测 / 挑战**：两者均不写 `evts`（`core.js:1414-1424` commitExam 只写 `db.exam`；`:1781` 注释「不调 rateWord，不碰 evts」；`commitChallenge` 只写 `db.challenge`）→ **不进入本指标**，其语义零改动。
- **与 SRS / 强度引擎**：只读 `evts`，不改 `lvl/due/st/wrong/wfix`、`strengthMode`、抽测排程；`strengthOf`/`strengthDue` 语义零改动。
- **展示位（裁决）：统计页独立全宽 `.card`**（G5 视觉规格 v1.1 §1 已落定）。
  - **位置**：`renderStats` 内「近 14 天有效完成率」卡之后、`strengthEntryHtml()`（仪表盘入口卡）之前，前置既有 `.section-gap`。**按 G5 的全页叙事顺序**：概览（四卡）→ 输入侧三卡（热力图 / 14 天 / 完成率）→ **结果侧（本块）** → 记录侧（抽测 / 节律 / 装订 / 星标）——位置本身承担「这是结果侧观测」的标记，与 D-054「不靠颜色区分不同性质」呼应。（v1.2 曾写「四卡之后、热力图之前」，v1.3 改按 G5 的叙事顺序，位置由视觉规格裁定。）
  - **不进 `.stat-cards` 栅格**（G5 实测：980px 下 `.stat-cards` 生成 5 条轨道，第 5 个 tile 填的是本就空着的第 5 轨、四卡宽度不变；真代价是**行高**——grid 行高等于最高项，新 tile 折行后高 ~208px vs 现有四卡 ~111px → **四卡被拉伸、每卡底部多出 ~98px 死白**；独立全宽块则四卡宽高逐像素零改动）。
  - **不进仪表盘**：G5 已核实仪表盘数据可得（`Core.loadDB()` 读 `localStorage['w365.db']`＝**与主程序同一存储键**、只读不写、已有兜底横幅）→ **改判统计页不是被可得性逼的**，而是三条设计理由：① D-054④ 命名约束在两页之间风险差最大（仪表盘整页以「记忆保持率 · 散点图」为题、侧栏写「保持率估计 = 强度分(0–6) ÷ 6」，把实测指标放进那页＝摆在「保持率」射程正中）；② 仪表盘 `.overview` 是 5 格**评级条**（记得牢/在巩固/需复习，青绿/青灰/琥珀橙），「不评价好坏」的实测 % 塞进评级条邻位会被读成第四档位，而统计页全页无评级语汇；③ **冷启动是主场景**（§5），主态可达性必须短——统计页是顶栏一级入口（一次点击），仪表盘需先点卡内「打开仪表盘 ›」再开新标签页。
  - **若 G0 仍改判仪表盘**，须另立卡并额外满足（G5 给出）：① 不进 `.overview` 评级条、单开 panel；② 用该页自有令牌（`--surface`/`--muted`/`--faint`/`--line`），不混 `app.css` 令牌；③ 用该页 mono 大写小标语汇，禁 30px 无衬线中文大数字；④ 该 HTML 不在本卡写入域内，须先解决写入域。
