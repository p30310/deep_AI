# G6 · 交互规格与验收设计（Interaction Spec）

> 边界卡 v1.0 · 2026-11-14 · 上级：`../README.md`、总纲 §12/§13
> 参考能力：`ai-eval-design`（把功能转成可判定断言）

## 1. 组标识与一句话职责

**G6**：把功能变成可测的交互——路径、状态、异常、反馈分级与逐条 AC，不写实现。

## 2. 默认调用触发

- 「梳理交互」「状态怎么走」「异常怎么处理」「验收走查」；
- 需要把 PRD 的功能描述转成 Given/When/Then 或可点走查件；
- 规格与实现出现冲突，需要出对照矩阵。

## 3. 独有产出（不可替代）

- 交互规格 MD：六条关键路径、统一七态（idle/ready/active/paused/done/empty/degraded）、四层信息层级、12 条异常矩阵、24 条可测 AC；
- 实现对照矩阵：符合 / 部分符合 / 冲突 / 规格层未实现 四态；
- 走查件 HTML：`单词365_v3.0_交互状态走查.html`、`单词365_v3.0_交互验收走查_R4-R5.html`；
- 功能原型：`单词365_v3.0_原型.html`。

## 4. 必需输入

G1 的 AC 与功能范围；v3.0 方案的数据契约与文案禁令；既有原型与设计令牌。

## 7. 组内 DoD

1. 每条 AC 可判定（断言明确、可通过/失败可复现）；
2. 每个状态可达且有入口与退出路径，无死状态；
3. 异常矩阵覆盖：空/加载/错误/权限/超时/重复/冲突/重试/撤销/降级；
4. 与实现对照给出四态计数，冲突项附最小修订建议（逐字）；
5. 走查件自包含、零外部依赖、可键盘操作；
6. 视觉严格沿用既有册页令牌，不新增风格。

## 8. 依赖与并行性 + 执行登记

- **上游**：G1（AC 与范围）；**下游**：G8（真机回归）。
- **并行性**：属 P1/P4 并行集，可在实现前先出规格；不写源码，因此不阻塞 G3/G4。
- **边界**：只出规格与走查，不改实现；实现组按建议自行落地，G6 不复核代码。
- **冻结条件**：R1–R5 已闭环，R6 真机回归前不再新增交互文档。
