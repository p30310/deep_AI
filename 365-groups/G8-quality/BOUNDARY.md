# G8 · 质量与一致性（Quality）

> 边界卡 v1.0 · 2026-11-14 · 上级：`../README.md`、总纲 §12/§13
> 参考能力：`ai-eval-design`、`enterprise-ai-delivery`（生产就绪与验收）

## 1. 组标识与一句话职责

**G8**：独立判定「做完了没有」——跑全量回归、核对分发一致性、评审跨交付物矛盾，只报不改。

## 2. 默认调用触发

- 「跑一下测试」「验收」「评审这批文档」「一致性检查」「能不能发」；
- 实现组声称完成，需要独立验证；
- 构建产物与源码不一致、测试数字对不上。

## 3. 独有产出（不可替代）

- 全量测试结论（A：**161 项 / 7 文件** @ 2026-11-14 21:03 起；B：13 套件 476 项，以当日实测为准）与逐文件计数；
- 独立验证脚本与结果（如 `qa_independent_verify.mjs`）；
- 缺陷清单（含复现步骤、严重度、归属组）；
- 跨交付物一致性评审（P0–P3 + 最小修复 + 验证用例）；
- `www↔dist/www` 逐字节一致性与 dist 边界核对结论。

## 4. 必需输入

各组改码清单、新增测试文件、构建输出、待评审材料与版本；PRD 的 AC 编号（验收权威）。

## 5. 可写范围

- `E:/WorkBudy_WorkSpace/word365/tests/**`（**仅新增独立文件**，不改既有用例）
- B 仓库 `tests/**`（仅新增独立验证文件）
- QA/评审记录（写入 `.workbuddy/memory/` 或专设评审节）
- 认领表中本组状态

## 6. 禁写清单

- 任何产品代码（只报缺陷，不改源码）
- `docs/prd-*.md`、`docs/design-*.md`（不替 G1/G2 改结论）
- 既有测试文件的断言（不得为通过而放宽）
- `dist/**`（只由 `build.ps1` 生成）

## 7. 组内 DoD

1. 全量测试 0 失败，且**显式列文件**（`node --test tests/` 在本机会报 MODULE_NOT_FOUND）；
2. `node tests/check-data.mjs` 通过（涉及数据时）；
3. B 仓库 `run-tests.ps1` 全绿 + `build.ps1` 重建 + `diff -r www dist/www` 一致；
4. 每个缺陷有：定位/证据 → 影响 → 严重度 → 最小修复 → 验证用例；
5. 评审结论区分「已确认缺陷 / 合理推断 / 待验证假设」；
6. 判定 NoOne 或给出路由（哪个组修）。

## 8. 依赖与并行性 + 执行登记

- **上游**：G3/G4/G5（实现完成并冻结写入）；**下游**：G1/G0（合并核验与归档）。
- **并行性**：属 P3 回归并行集；A 仓库与 B 仓库回归可内部并行。
- **硬约束**：回归窗口内其他组不得写代码（否则基线漂移，结论作废）。
- **命令渠道**：B 仓库须用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File '...'`，不可从 Bash 直调。
