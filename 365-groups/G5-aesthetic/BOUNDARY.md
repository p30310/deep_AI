# G5 · 美学与视觉封装（Aesthetic / Folio）

> 边界卡 v1.0 · 2026-11-14 · 上级：`../README.md`、总纲 §12/§13
> 参考能力：OPC 美学宪章（Folio 01/02/03、Skins、Five Bindings）自有方法，不套 AI 产品技能

## 1. 组标识与一句话职责

**G5**：用独立覆盖层重塑视觉与仪式，不改功能逻辑与数据，做到「加一行引入、删两行回退」。

## 2. 默认调用触发

- 「换肤」「皮肤」「风格切换」「开箱仪式」「交互观感」「多套书装」；
- 需要做美学对照页、定价与封装提案；
- 视觉与基础样式冲突需要会签。

## 3. 独有产出（不可替代）

- B 仓库独立样式层：`folio.css`、`motion.css`、`opening.css`、`skin-*.css`；
- B 仓库独立脚本层：`motion.js`、`opening.js`、`skin.js`；
- 独立测试：`opening.test.js`、`skin.test.js`；
- 工作区对照页：`单词365_册页皮肤_前后对照.html`、`单词365_交互节律_前后对照.html`、`单词365_五套书装_对照.html`、`单词365_开箱仪式_交互原型.html`；
- 美学宪章与定价提案（`单词365_美学宪章*.{md,html}`）。

## 4. 必需输入

G1 的品牌语/定位结论（代码可先行、结论需会签）；B 仓库现有令牌结构（L1→L2→L3）；无障碍基线（WCAG AA、44px、焦点双环、三种系统偏好）。

## 5. 可写范围

- B 仓库 `www/css/{folio,motion,opening,skin-*}.css`
- B 仓库 `www/js/{motion,opening,skin}.js`
- B 仓库 `tests/{opening,skin}.test.js`
- B 仓库 `index.html` **仅引入行**
- B 仓库 `README.md` 的独立章节（§十九/§二十，需独占认领）
- 工作区 `单词365_*.html`、`单词365_美学宪章*.md`

## 6. 禁写清单

- B 仓库 `www/css/app.css`、`www/js/app.js`、`www/js/core.js`、`www/js/books.js`、`www/js/migrate.js`
- A 仓库 `word365/**` 全部
- 任何功能逻辑、数据字段、SCHEMA
- 不得删除既有风格（经典版必须完整保留）

## 7. 组内 DoD

1. 一键回退成立：删 `index.html` 的对应 link/script 两行即恢复；
2. 不新增框架/构建/CDN 字体；字体本地分发；
3. WCAG 2.1 AA 复测（含新色板小字对比度）、44px、焦点双环、`prefers-*` 三偏好；
4. 独立测试全绿；`build.ps1` 重建后 `www↔dist/www` 逐字节一致；
5. 对照页明确标注「界面语汇示意，非运行截图」；
6. 不把【提案】写成【实测】，定价标注为提案锚点。

## 8. 依赖与并行性 + 执行登记

- **上游**：无硬依赖（视觉可先行；品牌/定价结论依赖 G1 会签）；**下游**：G8（回归与分发核验）。
- **并行性**：属 P1 前置并行集，且因在 B 仓库独立层，可与 G3/G4 **全程并行**。
- **串行点**：B 仓库 `index.html` 引入行（与 G4 的 A 仓库 `index.html` 不是同一文件，但仍按认领表顺序）；B 仓库 `README.md` 章节独占。
- **风格冲突**：与 G4 的基础组件（圆角/语义描边）冲突时两会签，G0 记录裁决。
