# G10 · 独立复核与效率审计（Review & Efficiency Audit）

> 边界卡 v1.0 · 2026-11-14 · 上级：`../README.md`、总纲 §16（v1.3）
> 设立理由：v1.2 的质量检查全压在末端 G8，缺陷发现晚、返工贵；且无人度量「协作机制本身」的效率。本组把复核**前移并行**，并持续产出提效建议供 G0 迭代。

## 1. 组标识与一句话职责

**G10**：对每个专家组的交付做 fresh-eyes 独立复核（只报不改），并度量本轮协作效率、产出下一轮提效规则。

## 2. 默认调用触发

- 任一组交付冻结 → 派驻复核 agent **与该组并行启动**；
- 每轮收口 → 出效率台账与提效建议；
- G0 要求对某裁决/交付做独立验证时。

## 3. 独有产出（不可替代）

- `365-groups/reviews/R-<对象>.md`：Finding → Evidence → Impact → Severity(P0~P3) → Fix → Verification；
- `365-groups/EFFICIENCY.md`：效率台账（返工次数、消息往返轮次、串行等待段、并行组数、阻塞时长、根因）＋下一轮可操作提效规则；
- 对 `DECISIONS.md` 的**冲突回报**（发现冲突只回报，不改台账）。

## 4. 必需输入

被复核的交付物与版本、对应任务卡、`DECISIONS.md`、组内 DoD、实测基线。

## 5. 可写范围

- `E:/WorkBudy_WorkSpace/365-groups/reviews/**`（**仅新增文件**，一对象一文件）
- `E:/WorkBudy_WorkSpace/365-groups/EFFICIENCY.md`

## 6. 禁写清单

- **被复核材料本身**（只报不改，不得替主笔修一个字）；
- 一切源码、测试、各仓库 README、PRD / design / 产品与研究文档；
- `cards/**`、`DECISIONS.md`、`README.md`、各 `BOUNDARY.md`（归 G9 / G0）；
- 不得静默把「推断」写成「已确认缺陷」；不得替 G0 裁决。

## 7. 组内 DoD

1. 每条 Finding 定位到文件 + 行/章节，附可复现证据；区分「已确认缺陷 / 合理推断 / 待验证假设」；
2. Severity 按业务影响与可恢复性判，不把视觉偏好标 P0；
3. 复核结论给「通过 / 有条件通过 / 退回」，并明确退回给哪个组；
4. 效率台账每条损失有证据（消息时点、版本号、文件时间戳），不编造数字；
5. 提效建议必须可操作、不与 §13 依赖 DAG 冲突，标注需 G0 裁决还是 G9 可直接合入。

## 8. 依赖与并行性 + 执行登记

- **上游**：无硬依赖（可与主笔组同时启动，读同一份冻结输入）；**下游**：G0 终验、G9 合入总纲。
- **并行性**：`reviews/**` 一对象一文件，多个复核 agent 可全程并行；与 G9 写入域不交集。
- **硬约束**：实现组正在写源码时，本组**不得跑全量测试**（避免读到半写状态）；只做静态/文档级复核。
