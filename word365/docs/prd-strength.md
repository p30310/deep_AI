## 1. 背景 / Problem / Goal / Non-goals

### 1.1 Problem

**【实测】** 到期间隔仍由固定表 `LADDER_DAYS = [1,2,4,7,15,30,60]`（core.js:14）决定，`rateWord` 的 `know` 分支按 `LADDER_DAYS[min(lvl,6)]` 取间隔（core.js:197-198）；复习到期判定为 `r.reps>0 && r.due>0 && r.due<=t`（core.js:269-271）。时长已接线（N4）、题型已按阶梯（N2，`resolveLadderMode` core.js:747-777），但**间隔本身对所有词、所有人都相同**。

**【实测】** 现状已有一个「记忆强度最低」的**只读代理**：`buildRebuildPack` 用 `(3 - lvl)` 打分（core.js:911），说明"强度"概念有落点，但它只是 `lvl` 的反相代理，**不反映作答历史**。新词记录 `newRecord`（core.js:132-150）无任何事件 / 历史 / 强度字段。

**【推断】** 固定阶梯不反映个体差异：有人 3 天就忘、有人 30 天仍记得；同一 `lvl` 的词对不同人的真实遗忘风险不同。

### 1.2 Goal

1. 引入**个体记忆强度**，以**叠加层**方式存在，`db.settings.strengthMode==='on'` 时接管 `due`，OFF 缺省走 `LADDER_DAYS`；保留固定阶梯为**可回退基线**（C4 维持）。
2. **分两阶段**：阶段一观测层（逐次作答事件采集 + 只读强度看板）零行为变更；阶段二叠加引擎（开关式 due 覆盖），开关默认 OFF。
3. 强度估计第一版用**可解释的启发式**（基于历史间隔与对错），不引入实时训练模型；不展示伪精确百分比。

### 1.3 Non-goals（可枚举、逐条可判定）

1. **不替换 / 不删除固定阶梯**，不改 `LADDER_DAYS` 常量值，仍为可回退基线（C4）。
2. **不改 `SCHEMA`**（恒 3，不抬）。
3. **不动 `w::` 主键体系**（`wordKey` core.js:34；义项拆卡属 #016 范畴，本卡不做）。
4. **不改 `rateWord` 三分支既有逻辑**，不改 `lvl/due` 现有计算的默认路径。
5. **不做账号 / 云同步**；事件数据仅本地存储。
6. **不改既有 SRS 默认行为**：新库 / 旧备份在 OFF 下的行为与改前逐字段一致。
7. **不做实时训练模型（ML）**，第一版仅可解释启发式。
8. **不做义项拆卡 / 抽测义项逻辑**（#016 范畴）。
9. 本 PRD **不含**强度看板 UI 实现（G1 禁写 `app.js`；若需只读视图由 G0 另行授权 / 另开子卡）。

## 4. 关键业务规则 / 状态

> 本章为【规划】；默认假设未拍板即按此执行（Open 见 §5）。

### 4.1 开关语义

- `db.settings.strengthMode` 二值：`'off' | 'on'`，**默认 `'off'`**（缺省即 OFF）。
- **仅** `'on'` 时强度函数接管 `due`；`'off'` 时固定阶梯为唯一到期来源。
- 切换本身**不回滚**既有评级结果，也不改 `lvl/st`；只影响"下一次到期计算读谁"。

### 4.2 事件写入时机与撤销

- 写入时机：**评级成功时**追加一条事件（含当时 `t` / `rating` / `interval` / `type`）；评级失败 / 无效评级不写。
- 题型 `type` 来源：由调用方在评级时提供（现状 `rateWord(db,key,rating)` 签名无题型入参，core.js:176）——**字段落点与传参方式由 G2 契约定**，G1 不替 G2 定实现。
- 撤销是否回滚事件：**默认假设 undo 时同步删除对应事件**；技术依据【实测】：`undoRate` 用 `snap.rec = clone(rec)` 整体还原（core.js:187/233-242），若事件写在 `rec.evts` 内则快照天然包含回滚。最终口径由 **G0** 拍板（OP-01）。

### 4.3 强度估计的可解释性

- 第一版用**可解释启发式**（基于历史间隔与对错），不引入 ML；输出须能被说明（例如与事件序列的间隔 / 正负反馈单调相关），但**不展示伪精确百分比**。
- 无事件时回退 `lvl` 代理（现状 `(3-lvl)` 口径，core.js:911），保证有确定性值。
- `st` 判定口径默认假设：强度模式仅接管 `due`，`st` 沿用现有 `lvl>=3 && interval>=7` 判定（core.js:199）——契约须声明该口径以便 STR-AC05 断言。

### 4.4 状态不变式（红线）

- `SCHEMA` 恒 3；`LADDER_DAYS` 恒 `[1,2,4,7,15,30,60]`；`w::` 主键体系不变；OFF 下 `rateWord` 三分支逐字段等价。
